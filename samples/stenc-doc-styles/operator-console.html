Scope Check

Assessment

The work is one coherent fixture-and-test slice because the spec and plan catalogs jointly define the renderer inventory.

Decomposition

Keep fixture authoring and evidence collection as separate reviewable slices while committing them as one catalog contract.

Architecture

Two independently reviewable slices add comprehensive fixtures first and then verify mirrored content, validation evidence, and semantic renderer inventory.

Tech Stack

  • Node.js node:test
  • Structured JSON fixtures
  • Dependency-free Stenc validator
  • Static HTML renderer

Current State

Existing examples demonstrate many fields in isolation, but no single spec-plan pair locks the complete component inventory.

Target State

Byte-identical example fixtures validate against schema v2 and drive a semantic renderer inventory test with an intentional production-class gap.

Scope

In

  • Comprehensive spec and plan fixtures
  • Stable semantic class assertions
  • Schema validation and mirror parity evidence

Out

  • Production renderer semantic class implementation
  • Production structured diagram rendering
  • Per-document component or style APIs

Risks

Risk

The catalog drifts when a validator field or rich primitive changes.

Mitigation

Review the catalog whenever validator constants or field-contract references change.

Risk

The intentional RED test is mistaken for malformed fixture evidence.

Mitigation

Run schema validation and mirror parity separately, and report the exact semantic class assertion failure.

Risk

Fixture content introduces a renderer-only source convention.

Mitigation

Use only current validator-known JSON fields and fixed rich primitives.
